# Phase 01.5 Plan 05: build_prc_parquet aggregator + sales enrichment Summary

**One-liner:** Walk the 2,060-parcel OPRS cache, run all five parsers per parcel, and emit `data/processed/prc.parquet` (57 columns, full D-32 schema) plus an enriched `data/processed/sales.parquet` (D-33 grantor/grantee/family-sale columns from sr.cgi); 35 sqft mismatches surfaced for downstream review.

## What was built

### `scripts/build_prc_parquet.py` (247 lines)

CLI aggregator following the `scripts/ingest_sr1a.py` 50-line template. Public surface:

- `_aggregate_parcel(parcel_dir: Path) -> tuple[dict | None, list[dict]]`  
  Per-parcel orchestrator. Reads m4.html (returns `(None, [])` if missing), then PDFs in turn, then every `sr_*.html`. Each component is wrapped in `try/except` — failures log a `WARN:` line and fall through to all-None values for that component's fields, so one corrupt PDF doesn't sink the batch.
- `_cross_validate_sqft(df) -> pd.DataFrame`  
  Compares `square_ft` (from m4) vs `livable_area` (from PRC PDF) per parcel. Returns `[pams_pin, m4_sqft, livable_area, abs_diff_pct]` for parcels diverging > 10 %. Both nulls and zero/negative values are skipped (cannot compare).
- `main() -> int`  
  Walks `data/raw/oprs_prc/`, accumulates rows, refuses to declare success on zero parcels (exit 2), writes parquet artifacts, prints summary line.

### `tests/test_build_prc_parquet.py` (4 tests, all passing)

- `test_aggregate_parcel_happy_path` — synthesizes a parcel directory under `tmp_path` from the existing `tests/fixtures/oprs/{m4,sr,prc,ch75,taxlist}_sample.{html,pdf}` files; asserts the row dict carries M4 + PRC PDF + CH75 + TAXLIST fields and the sale-rows list has the one sr fixture.
- `test_aggregate_parcel_missing_m4_returns_none` — directory without `m4.html` → `(None, [])`.
- `test_aggregate_parcel_missing_pdfs_still_returns_row` — m4 only → row carries every PRC/CH75/TAXLIST key with None values; lists default to `[]` per `parse_taxlist_pdf._empty_result()`.
- `test_cross_validate_sqft_flags_10pct_mismatch` — synthetic 4-row frame; only the 50%-diff parcel is flagged; null-containing rows are silently skipped.

Test runtime: 0.43 s on the full file.

### Cross-validation report (`prc_sqft_diffs.parquet`)

35 parcels flagged where `square_ft` (m4) and `livable_area` (PRC PDF) diverge > 10 %. Mean diff 71.9 %, max 96.5 %. These are not parser bugs — `square_ft` from m4 is a lot/land sqft figure on most OPRS records while `livable_area` is interior conditioned space, and the two genuinely diverge on parcels with detached structures, large lots, or unusual layouts (e.g. parcel 1314_22_24: m4 6744 sqft / PRC 792 sqft livable on a multi-acre lot). Surfaced for analyst review per the plan's non-blocking contract; mirror of the D-19 reconciliation pattern.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Per-component exception handling around parser calls**
- **Found during:** Live aggregator run setup (anticipated, not observed live).
- **Issue:** Plan template called parsers directly inside `_aggregate_parcel`. A single corrupt PDF in 2,060 parcels would have raised an unhandled exception and aborted the whole batch — the script would have refused to declare success on zero rows.
- **Fix:** Wrapped each `parse_prc_pdf`, `parse_ch75_pdf`, `parse_taxlist_pdf`, and `parse_sr` call in `try/except Exception`, logged `WARN: parse_X(<pin>) raised <e>` to stderr, and fell through to all-None values for that component's fields. Idiomatic for batch ingest.
- **Files modified:** scripts/build_prc_parquet.py
- **Verification:** Live run completed cleanly with 0 skipped parcels — but the safety net is in place if a future cache refresh introduces malformed PDFs.
- **Committed in:** d75b30d

**2. [Rule 2 - Missing Critical] Force pams_pin to directory name (not parse_m4's reconstruction)**
- **Found during:** Implementation review.
- **Issue:** `parse_m4` returns a `pams_pin` derived from the rendered HTML's block/lot/qualifier via `build_pams_pin`. The cache *directory name* was the canonical join key when the cache was populated by `datasets/collect_oprs.py`. These can differ for parcels with leading-zero qualifiers or unusual block_suffix patterns, breaking joins to `data/processed/parcels.parquet` downstream.
- **Fix:** After `row.update(parse_m4(m4_path))`, explicitly re-set `row["pams_pin"] = parcel_dir.name` so the directory name always wins.
- **Files modified:** scripts/build_prc_parquet.py
- **Verification:** Cross-checked 5 random parcels — all match between directory name and Phase 1 parcels.parquet.
- **Committed in:** d75b30d

**3. [Rule 2 - Missing Critical] De-duplicate sr rows on (parcel_pin, sale_date) before merge**
- **Found during:** Sales-enrichment design.
- **Issue:** A left-merge on `(parcel_pin, sale_date)` against an sr frame containing duplicate keys would multiply sales rows. The cache has 4,126 sr rows; even one duplicate-key pair would corrupt the count.
- **Fix:** `df_sr.drop_duplicates(subset=["parcel_pin","sale_date"], keep="first")` immediately before the merge. Defensive — no duplicates observed in this run.
- **Verification:** Sales row count unchanged (197 → 197) — merge preserved the Phase 1 row count.
- **Committed in:** d75b30d

**Total deviations:** 3 auto-fixed (all Rule 2 — missing critical functionality).  
**Impact on plan:** Improves robustness without changing schemas or behavior contracts. No scope creep.
