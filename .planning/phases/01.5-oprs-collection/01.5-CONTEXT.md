# Phase 1.5: OPRS Comprehensive Collection - Context

**Created:** 2026-04-29
**Status:** Ready for planning
**Trigger:** Phase 1 verification revealed MOD-IV does not carry bedrooms/bathrooms/condition fields. Original Phase 2 hedonic spec is unbuildable on Phase 1 data alone. OPRS publishes those fields in the PRC PDF.

<domain>
## Phase Boundary

Cache the full set of Tier 1-4 OPRS Property Record Card components for every class-2 Fair Haven parcel, plus the Rutgers Bloustein MOD-IV historical CSV series 1989-2025. Produce two new processed artifacts (`prc.parquet`, `modiv_history.parquet`) keyed by PAMS_PIN that Phase 2 can consume without further data acquisition.

**In scope:**
- m4.cgi (with hist=1) per parcel
- sr.cgi per discovered sale ssi (variable count per parcel)
- prc.cgi → PDF Property Record Card per parcel (with HTTP-header strip workaround)
- ch75.cgi → Chapter 75 annual notice PDF per parcel
- taxlist.cgi → current-year tax-list page PDF per parcel
- Bloustein 1989-2025 CSV per year (37 files; already in hand)
- Parsers that join OPRS components into `prc.parquet` and Bloustein into `modiv_history.parquet`

**Out of scope (deferred to v2 — see `.planning/deferred/oprs-tier-c.md`):**
- Tax Appeals (ASP.NET VIEWSTATE — different infrastructure)
- County Clerk deed images (10-50 GB scope expansion)
- Tax map sheets, rate certifications, subdivision maps, consolidated records search
</domain>

<decisions>
## Implementation Decisions

### Collection (already implemented in `datasets/collect_oprs.py`)

- **D-20 (URL encoding)**: 28-char `l02` token for m4.cgi: `DDDD BBBBB SSSS LLLLL XXXX QQQQQ M`. Suffixes right-justified with underscore fill; qualifier left-justified. Verified against live samples.
- **D-21 (Per-parcel processing)**: Each parcel completes fully before moving to the next. After m4 fetch succeeds, parser extracts ssi values and queues sr.cgi work for THIS parcel inline.
- **D-22 (Content validation)**: Every response is rejected unless its rendered Block AND Lot integers match the requested values. Empty templates (200 OK + ~13 KB blank PRC) are NOT cached.
- **D-23 (`.no_sale` markers)**: sr.cgi for parcels/ssis with no detail on record returns the empty template legitimately. Detected by `// // ` date placeholder. Cached as `<component>.no_sale` markers (~20 bytes) so we never refetch.
- **D-24 (Atomic writes)**: Every cache file writes to `<path>.tmp` first and renames on success. Interrupted runs leave NO partial files.
- **D-25 (Batch + VPN-swap)**: `--batch N` caps requests per invocation. Operator manually swaps VPN exit between batches. `--max-error-rate` aborts cleanly when rolling error rate exceeds threshold.
- **D-26 (No identifying UA)**: Standard Chrome-Mac User-Agent string. No contact email. Per user directive — operational anonymity over politeness convention.

### Collection (NEW for Phase 1.5)

- **D-27 (PDF endpoint pattern)**: For prc.cgi, ch75.cgi, taxlist.cgi — each is a 2-request flow: hit the cgi (returns HTML pointing to a session-bound `tmp/<random>.pdf`), then GET the temp PDF URL with the same session. Both requests count toward batch budget.
- **D-28 (prc.cgi HTTP-header strip)**: Upstream Apache returns the PDF binary with `Content-Type: text/html`, and the response body has the literal HTTP envelope prepended. Slice from the `%PDF` marker to extract the real PDF.
- **D-29 (Cache layout)**: `data/raw/oprs_prc/<pams_pin>/{m4.html, sr_<ssi>.html, prc.pdf, ch75.pdf, taxlist_<year>.pdf}`. Each component independently cached so basic ↔ comprehensive ↔ "with PDFs" upgrades only fetch missing pieces.
- **D-30 (PDF validation)**: After fetch, validate by `body.startswith(b"%PDF")` (after header-strip if applicable) AND that pdfplumber can extract page 1 text. Otherwise reject and retry.
- **D-31 (Bloustein historical)**: Already collected via `datasets/collect_bloustein.py`. 37 files at `data/raw/bloustein_modiv/2026-04-29/mod_iv_{1989..2025}.csv`. All ≥2,121 rows. Loader is the new work.

### Parsing (Phase 1.5 deliverables)

- **D-32 (`prc.parquet` schema)**: One row per parcel. Columns:
  - From m4.html: `pams_pin`, `block`, `lot`, `qualifier`, `prop_loc`, `square_ft`, `year_built`, `style_code`, `bldg_desc`, `land_desc`, `acreage`, `zone`, `map_page`, `class`, `current_taxes_1h`, `current_taxes_2h`, `updated_date`
  - From prc.pdf: `bedrooms`, `bathrooms`, `room_count`, `kitchens`, `livable_area`, `eff_age`, `first_story_sf`, `upper_story_sf`, `half_story_sf`, `condition`, `quality_grade`, `foundation`, `exterior`, `roof_type`, `roof_material`, `heating_type`, `heating_sf`, `ac_type`, `ac_sf`, `fireplaces`, `garage_type`, `garage_sf`, `porch_sf`, `patio_sf`, `shed_sf`, `sewer`, `water`, `gas`, `topography`, `road_type`
  - From ch75.pdf: `prior_year_assessment`, `current_year_assessment`, `assessment_change_pct`, `notice_year`
  - From taxlist.pdf (current year): `actual_tax_paid_total`, `tax_1h_paid`, `tax_2h_paid`, `special_tax_codes`, `deduction_codes`, `deduction_amount`
- **D-33 (`sales.parquet` enrichment)**: Existing sales.parquet (from Phase 1) gains additional columns from sr.cgi: `grantor`, `grantee`, `family_sale_flag`, `sales_ratio_assessor`, `remarks`, `additional_blocks_lots`, `serial_number`. Joined by (parcel_pin, sale_date) — multiple sales per parcel.
- **D-34 (`modiv_history.parquet` schema)**: One row per (parcel_pin, year). Columns: parcel_pin, year, owner_name, prop_loc, land_value, improvement_value, net_value, deductions, deed_book, deed_page, deed_date, sale_price, sale_assessment, sale_nu_code, year_built, building_description, calculated_acreage, num_dwellings. From Bloustein CSV `mod_iv_{year}.csv` × 37 years × ~2,150 rows = ~80,000 rows total.
- **D-35 (Owner-name handling)**: Bloustein CSVs DO contain owner names (NJGIN's are redacted). Keep `owner_name` in modiv_history.parquet (private analytical use only). For any public artifact, strip per Daniel's Law per existing LEGAL-01/02.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `datasets/collect_oprs.py` already implements: per-parcel processing, atomic writes, content validation, no_sale markers, error-rate auto-abort, batch budget, status reporter. PDF endpoints are the only addition.
- `datasets/collect_bloustein.py` is complete and tested.
- `src/fairhaven_tax/ingest/manifest.py` provides sha256 + atomic-write primitives reusable for any new download.

### Patterns to follow

- New collector components: add `prc.pdf`, `ch75.pdf`, `taxlist_<year>.pdf` to the COMPONENTS list; one URL builder per type; validators check `b"%PDF"` marker.
- New parsers: one Python module per source under `src/fairhaven_tax/ingest/oprs/` (e.g., `parse_m4.py`, `parse_sr.py`, `parse_prc_pdf.py`, `parse_taxlist_pdf.py`, `parse_ch75_pdf.py`). Each module has one function that takes a Path and returns a dict of canonical fields. The cross-parcel aggregation (parquet write) lives in a script.
- Bloustein loader: `src/fairhaven_tax/ingest/bloustein.py` — loads all 37 CSVs, normalizes column names (Bloustein has 132 columns; we keep ~25), writes `modiv_history.parquet`.

### Integration points

- Phase 2's hedonic now reads `prc.parquet` joined to `parcels.parquet` for full feature set.
- Phase 2's CDF gap test reads `modiv_history.parquet` for the full 1989-2025 sale-assessment ratio universe (vs. just SR1A 2020-2025 alone).
