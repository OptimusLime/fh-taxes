## Field-Extraction Regexes (Reference)

### parse_prc_pdf

Anchored on labeled rows in the joined-page text:

| Field | Regex anchor (Python re, simplified) |
|------|----|
| bedrooms / bathrooms / room_count | `Room Count:\s*Tot:\s*(\d+)\s*Bed:\s*(\d+)\s*Bth:\s*(\d+)` |
| kitchens | `Kitchen:\s*Mod:(\d*)\s*Avg:(\d*)\s*Old:(\d*)` (sum) |
| livable_area | `Livable Area:\s*([\d,]+)` |
| eff_age | `Eff Age \(Years\):\s*(\d+)` |
| first/upper/half_story_sf | `(?:FIRST\|UPPER\|HALF) STORY\s+([\d,]+)` (HALF may omit `SF`) |
| condition / foundation / exterior / roof_type / roof_material / quality_grade | `Label:\s*([A-Z][A-Z /]+?)(?:\s{2,}\|\n\|$)` |
| sewer / water / gas / topography / road_type | `Label:\s*([A-Z][A-Z /]*?)(?:\n\|$)` |
| heating_type + heating_sf | `^([A-Z…]*(?:HOT (?:AIR\|WATER)\|HEAT\|BASEBOARD\|FURNACE\|STEAM\|RADIANT)…)\s+([\d,]+)\s*SF` |
| ac_type + ac_sf | `^(AC\s*\([A-Z…]+\)\|CENTRAL AC\|AC\s+[A-Z…]+)\s+([\d,]+)\s*SF` |
| fireplaces | `FIREPLACE[A-Z0-9 ]*?\s+(\d+)$` |
| garage_type + garage_sf | `^(GARAGE[A-Z0-9 \-]*?)\s+([\d,]+)\s*SF` |
| porch_sf / patio_sf / shed_sf | `(?:PORCH\|PATIO\|SHED)[A-Z0-9 \-]*?\s+([\d,]+)\s*SF` |

### parse_ch75_pdf

The legal notice form lacks labeled rows in extracted text. We anchor on the unique three-amount line (land/improvement/total):

- `^([\d,]+)\s+([\d,]+)\s+([\d,]+)$` — group 3 = current_year_assessment
- After that anchor, the next standalone comma-separated amount with magnitude ≥ current/10 = prior_year_assessment
- `\b(20\d{2})\b` — first match = notice_year
- assessment_change_pct = (curr - prior) / prior * 100

### parse_taxlist_pdf

Anchored on the 4-line per-parcel block:

- Line 0: `^(\d+)\s+\S+\s+n/a\s+(\d+)\s+(\d+)\s+(\d{2})\s+(\d*\.\d+)$` → block, land, total, ded_code, ded_amt
- Line 1: first whitespace-token must equal the requested lot
- Line 2: last `.`-bearing token = total tax
- Line 3: last token = 1H tax; second-to-last digit-only token = special_tax_code
- 2H = total - 1H

## Decisions Made

1. **parse_taxlist_pdf signature deviates from plan.** The plan declared `parse_taxlist_pdf(path: Path) -> dict`. But OPRS taxlist PDFs are borough-wide multi-parcel pages (page 67 contains parcels 29/10 through 30/16+). With only `path` we cannot identify which row to return. **Resolution:** add required `block` and `lot` kwargs to the public signature. This is a Rule 2 deviation (missing critical functionality — the parser as plan-specified would be unusable). Documented under `## D-32 Schema Deviations` below.
2. **Coercer helpers duplicated per parser** (rather than factored into `src/fairhaven_tax/ingest/_coerce.py`). The plan explicitly says "copy verbatim — keep parsers self-contained". Defer the factoring to a refactor commit when the 4th parser appears.
3. **ch75 prior-year-assessment heuristic** uses both position (must appear after the three-amount row) AND magnitude (must be ≥ current/10) to avoid matching the tax-bill `$11,543.00` amount as a candidate.
4. **2H tax computed not parsed.** The taxlist row format prints `total` and `1H` only; 2H is implicit. Computing 2H = total - 1H matches the well-known NJ semi-annual billing convention.
5. **Corrupt PDF policy is "graceful":** parsers return all-None dicts (with empty lists for taxlist) rather than raising. This matches the plan's "gracefully return None or partial dicts" behavior contract and lets the aggregator skip rows without aborting the batch.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] parse_taxlist_pdf required block/lot parameters**
- **Found during:** Task 2 (parse_taxlist_pdf design)
- **Issue:** Plan signature was `parse_taxlist_pdf(path) -> dict` but the underlying PDF is a multi-parcel borough page. Without (block, lot) the parser would either return arbitrary first-row data, or attempt to return all rows (changing the dict signature into list[dict]) — both worse than adding a selector.
- **Fix:** Made `block` and `lot` required parameters. Caller (the aggregator script in Plan 05) supplies them from the parcel directory name (`1314_30_1` → `block=30`, `lot=1`).
- **Files modified:** src/fairhaven_tax/ingest/oprs/parse_taxlist_pdf.py
- **Verification:** All 9 tests in test_oprs_parse_taxlist_pdf.py exercise the new signature; the unknown-parcel test confirms graceful-Nones behavior.

## Issues Encountered

- ch75.pdf trips pdfplumber's MediaBox-missing assertion. Resolved by adding pdfminer.six fallback (already a known pattern in `datasets/collect_oprs.py::_pdfplumber_page1_ok`).
- PRC PDF text extraction is column-mangled (e.g. "Sewer: SEW/WATER" actually contains the *combined* sewer/water value due to text-flow extraction). Resolved by using line-end anchors and accepting that "SEW/WATER" semantically maps to `sewer="SEW/WATER"`, `water=None`, `gas="SEWER ONLY"` (the gas-line text is itself an OPRS encoding artifact). This is the parser's faithful representation of the OPRS source.
