## BLOUSTEIN_TO_CANONICAL Map (for future maintenance)

The 132-column Bloustein schema is uniform across 1989-2025 (verified by diffing 1989 vs 2020 vs 2025 headers — identical). The canonical rename map:

| Bloustein source            | Canonical target       | Notes |
| --------------------------- | ---------------------- | ----- |
| property_id_blk             | _block (intermediate)  | feeds build_pams_pin |
| property_id_lot             | _lot                   | feeds build_pams_pin |
| property_id_qualifier       | _qualifier             | empty for most parcels |
| street_address              | _street_address        | feeds owner_mailing_address |
| city_state                  | _city_state            | feeds owner_mailing_address |
| property_location           | prop_loc               | physical address of parcel |
| building_description        | building_description   | e.g. "1.5S-F-R-1U" |
| land_value                  | land_value             | Decimal |
| improvement_value           | improvement_value      | Decimal |
| net_taxable_value           | net_value              | Decimal — primary assessment |
| deduction_amount            | deductions             | Decimal — sr/vet/disable etc. |
| deed_book                   | deed_book              | str |
| deed_page                   | deed_page              | str |
| deed_date_MMDDYY            | _deed_date_raw         | parsed ISO → date |
| sale_price                  | sale_price             | Decimal — most-recent sale $ |
| sale_assessment             | sale_assessment        | Decimal — assessor value @ sale |
| sale_sr1a_non_usable_code   | sale_nu_code           | str |
| year_constructed            | _year_built_raw        | int |
| calculated_acreage          | calculated_acreage     | Decimal |
| number_of_dwellings         | _num_dwellings_raw     | int |

The 114 unmapped columns (sptax, exemption details, tenant_rebate, etc.) are dropped at projection time. Full list available via `awk 'NR==1' data/raw/bloustein_modiv/2026-04-29/mod_iv_2020.csv | tr ',' '\n'`.

## Year-Specific Quirks

- **Schema is uniform across 1989-2025** — same 132 columns, same names, no drift. Verified via byte-exact diff of headers.
- **Older years (1989-2000) have many empty fields** — particularly `deed_book`, `deed_page`, `deed_date`, `calculated_acreage`. These are legitimate gaps (older records weren't fully digitized) and the loader tolerates them (None on missing).
- **Date format is ISO `YYYY-MM-DD`** despite the legacy column name `deed_date_MMDDYY`. The coercer attempts ISO first, then falls back to `MM/DD/YYYY`, `MM/DD/YY`, and `YYYYMMDD`.
- **`sale_price=0` and `sale_price=''`** both treated as missing (Bloustein uses 0 as a missing-data sentinel). This matches the SR1A `_parse_int_money` convention.

## Decisions Made

1. **owner_name → owner_mailing_address rename.** Plan/CONTEXT D-35 asserted Bloustein carries owner names. Verified directly: it does not. The closest signal is `street_address + city_state` (where the tax bill is sent). Renamed the canonical field to reflect what's actually there. Spirit of D-35 (private-use-only, strip on Phase 3 export) preserved.
2. **deed_date format.** Despite column name `deed_date_MMDDYY`, the actual format is ISO `YYYY-MM-DD`. Coercer tries ISO first.
3. **Manifest skip.** `datasets/collect_bloustein.py` does not currently write a manifest.json. The script logs this gap; either the collector should be extended (deferred), or the loader continues to skip verification.
4. **`sale_price=0` → None.** Bloustein uses 0 as a missing-sale sentinel — `_to_decimal` returns None for 0 to keep CDF gap-test ratios well-defined.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan asserted owner_name column existence; Bloustein does not provide it**

- **Found during:** Task 1 (loader implementation, after CSV header inspection)
- **Issue:** PLAN.md and CONTEXT.md D-35 both stated Bloustein CSVs contain owner names, with the implication that loader/parquet retains `owner_name` and Phase 3 export strips it for Daniel's Law compliance. Direct inspection of the 132-column Bloustein header (verified across 1989, 2020, 2025 — schema identical) shows NO owner-name column. The closest fields are `street_address` + `city_state`, which is the OWNER MAILING ADDRESS (where tax bills are sent). For absentee-owner detection (out-of-town vs. in-FH), the mailing address is the actual signal — even when an owner name were present.
- **Fix:** Renamed canonical column `owner_name` → `owner_mailing_address`; loader composes it from `{street_address}, {city_state}`. The `must_haves.truths` claim "owner_name retained" is satisfied in spirit (owner-identifying data retained for private analytical use) though the column name differs.
- **Files modified:** src/fairhaven_tax/ingest/bloustein.py (CANONICAL_HISTORY_COLS, BLOUSTEIN_TO_CANONICAL, _build_mailing_address), tests/test_bloustein.py
- **Verification:** Test `test_parse_bloustein_year_owner_mailing_address_combined` confirms Rumson out-of-town owner produces "29 CIRCLE DRIVE, RUMSON, NJ"; live parquet has 80,329/80,329 (100%) rows with non-null owner_mailing_address.
- **Committed in:** a5a30e4

**2. [Rule 1 - Bug] Plan claimed deed_date column is MMDDYY format; actual format is ISO**

- **Found during:** Task 1 (date coercer design)
- **Issue:** Plan implied YYMMDD-style date parsing similar to SR1A. Real Bloustein CSVs emit ISO `YYYY-MM-DD` (verified rows 1, 2, 3 of mod_iv_2020.csv).
- **Fix:** `_to_date` tries ISO first, with fallback formats for resilience.
- **Files modified:** src/fairhaven_tax/ingest/bloustein.py
- **Verification:** Test `test_parse_bloustein_year_deed_date_iso_parsed`.
- **Committed in:** a5a30e4
