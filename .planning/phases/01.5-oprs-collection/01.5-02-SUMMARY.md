All 47 failures were content-validation rejections of legitimate empty/not-found server responses:
- 7× the recurring `1314_35_31` empty-form anomaly
- 12× block-79 missing-taxlist data gaps × 3 batch hits each
- 4× transient network errors (1 burp at 01:01 ET on parcels 53_3 → 53_6, all auto-recovered on subsequent batches via the idempotent `parcel_needed_components` check)

## Critical bugs caught + fixed during the run

1. **`parcel_needed_components` two-pass design** (commit `fed1852`): originally returned only `[m4]` on first visit, queueing PDFs only on a subsequent invocation. Caused batch 1 to do m4-only for ~830 parcels with zero PDF progress. Fixed by inline-queueing all 3 PDFs alongside sr items after m4 success — single-pass full 4-tier per parcel.
2. **prc/ch75/taxlist URL params + regex** (commit `4bcccc5`): pre-flight live tests revealed unit tests had been against mocked data only. Real OPRS uses `h00/h01/h02/ccdd` not `district/l02`, and uses unquoted `href=` / `src=` in HTML responses. Fixed before the overnight run.
3. **ch75 PDF validation** (commit `4bcccc5`): pdfplumber chokes on PDFs whose MediaBox is missing. Added pdfminer.six fallback (same engine pdfplumber uses internally) for graceful handling.
