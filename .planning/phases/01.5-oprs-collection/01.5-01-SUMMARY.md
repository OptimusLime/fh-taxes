# Phase 01.5 Plan 01: OPRS PDF Endpoint Extension Summary

**One-liner:** Extended `datasets/collect_oprs.py` with prc.pdf, ch75.pdf, and taxlist_<year>.pdf endpoints implementing D-27 (two-request session-bound flow), D-28 (HTTP-header strip via `%PDF` marker slice — prc-only), and D-30 (PDF validation: marker check + pdfplumber page-1 extraction). 13 unit tests cover URL builders, the validator's PDF branch, the tmp-href regex, and the two-step fetch with prc-only strip. Plan 02 can now run `--mode comprehensive` and pull the bedroom/bathroom/condition data the Phase 2 hedonic needs.

### Two-request flow design (D-27)

```
client                      tax1.co.monmouth.nj.us
  │
  │  GET /cgi-bin/prc.cgi?district=1314&l02=...    [request 1]
  │ ────────────────────────────────────────────► │
  │                                                │  generate session-bound
  │  200 OK  text/html                             │  /tmp/<random>.pdf
  │ ◄─────────────────────────────────────────── │
  │  body: <html>... href="/tmp/abc.pdf" ...</html>
  │
  │  regex out href, resolve against TAX1_HOST
  │
  │  GET /tmp/abc.pdf      (same Session)          [request 2]
  │ ────────────────────────────────────────────► │
  │                                                │
  │  200 OK  Content-Type: text/html  (sic)        │
  │  body: HTTP/1.1 200 OK\r\nContent-Type: ...\r\n\r\n%PDF-1.4...
  │ ◄─────────────────────────────────────────── │
  │
  │  if component == COMPONENT_PRC:
  │      body = body[body.find(b"%PDF"):]   ← D-28
  │
  │  validate: body.startswith(b"%PDF") and len ≥ 500
  │  write atomic to data/raw/oprs_prc/<pin>/prc.pdf
  │  pdfplumber.open + extract_text(page 1) sanity check
  ▼
```

Both requests count toward the batch budget; the caller sees `requests_made=2` per successful attempt.

### Validator extension (D-30)
`_validate(component, body, ...)` gains a PDF-leading branch:
```python
if component.endswith(".pdf"):
    if not body.startswith(b"%PDF"):
        return False, "no_pdf_marker"
    return True, "ok"
```
Header strip happens upstream in `_fetch_pdf_two_step`, so by validation time the body should already begin with `%PDF`.

### fetch_component signature change
Old: `(ok, status)`
New: `(ok, status, requests_made)` where:
- cached → `(True, "cached", 0)`
- HTML success → `(True, "ok", 1)`
- PDF success → `(True, "ok", 2)`
- failure → `(False, last_status, sum_of_requests_across_retries)`

Single internal caller (`run_batch`) updated; `state.requests_done += max(requests_made, 1) if status != "cached" else 0`.

### Workload extension
`parcel_needed_components` in comprehensive mode now appends `prc.pdf`, `ch75.pdf`, and `taxlist_2026.pdf` after enumerating sr ssis (each independently cached per D-29).

### Status reporter extension
`report_status` in comprehensive mode now reports cached/pending counts per PDF component and factors the 2x request cost into the rough remaining-requests estimate.

## pdfplumber dependency

Already in `pyproject.toml` (`pdfplumber>=0.11`). Now imported at module top of `collect_oprs.py` for the post-write page-1 extraction sanity check. Module-level import (not lazy) — the project assumes the venv is the only execution surface, and pdfplumber is a small pure-Python+pdfminer.six install.

## Deviations from Plan

None requiring escalation. Three minor deltas worth noting:

1. **Test count**: plan target was "10+ tests"; delivered 13 (added two extra: a relative-href regex test and a missing-href two-step test) for tighter coverage of edge cases observed while writing the implementation.
2. **`_fetch_pdf_two_step` signature**: returns `(status_code, body | None, requests_made: int)` with `body=None` cases distinguished from network errors (status_code 0 vs >0). The plan's behavior block says "1 if cgi step fails"; I kept that exact contract, and additionally return `(200, None, 1)` if the cgi succeeded but lacked a tmp href (a structural failure rather than a network failure). Added a unit test covering that branch.
3. **Header-strip placement**: applied inside `_fetch_pdf_two_step` (before returning) rather than inside `fetch_component` after the call. Net effect identical, but keeps `_validate` cheap and ensures any caller of `_fetch_pdf_two_step` gets the cleaned body.

No D-27/D-28/D-30 contracts were modified.
